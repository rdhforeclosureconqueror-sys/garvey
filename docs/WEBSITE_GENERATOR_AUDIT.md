# GARVEY website generator audit and repair

Audited September 28, 2026. Repository: `rdhforeclosureconqueror-sys/garvey`.
Production `/api/version` returned `cc1b7b954f23463b81ab009c33a99142bd02c2d4`, matching the main branch checked out for this audit. Production checks were read-only; no customer records or generated sites were changed.

## Finding

The feature existed, but discovery, the form contract, template rendering, and publication were disconnected. It was not a single hidden toggle.

| Area | Confirmed original behavior | Repair |
| --- | --- | --- |
| Discovery | Owner homepage no longer linked to templates or website intake. | Visible Websites navigation, Create a Website action, and Website Builder quick access. |
| Catalog | Five records: Metropolis, Aroma Spa, Mobile App Landing, Rewards Premium Shell, GARVEY Premium Shell. Only the first three had website template directories. | Five functional native layouts: Clean, Modern, Service, Local, Personal. Original five entries remain accessible as reference previews. |
| Intake contract | Form omitted `template_type`/`template_id`; server required one. | Editor selects and submits a supported layout. Older content payloads can use a saved native selection or Clean. |
| Success contract | Materializer returned only `{site_url}`; form required `success`. | Consistent `{success, tenant, template_id, site_url}` response, followed by a visible published link. |
| Rendering | `/t/:slug/site` always returned the same Garvey tool hub; selected design was only a link. | The existing `generateTenantSite` renders the chosen native design with the submitted business content. |
| Content | File-copy materializer only replaced three tokens, with tenant slug/default labels rather than the submitted content. Imported templates were not integrated with those business fields. | Headline, subheadline, services, story, CTA, color, logo, phone, location, and hours appear in the rendered page. |
| Hosting | Template selection posted to the frontend origin; intake preview/redirect used relative backend-only paths. | Public catalog works statically; editor redirects to the backend host before owner-session requests. Returned canonical links use that same host. |
| Persistence | File-copy output lived under `public/sites`, while the form redirected to a different dynamic page. | New flow persists the site in existing PostgreSQL `tenant_config.site`; public output uses `/t/:slug/site`. No filesystem publishing dependency. |
| Ownership | Template select and generate endpoints had no owner-session check. | Requires a verified server-side owner session and matching tenant, with JSON-only mutations. Also guards the legacy activation entry that calls the materializer. |
| Draft versus published | No real preview/save separation. | Preview renders without writes. Publishing is explicit. Failed writes remain errors and do not report success. |

The bundled Aroma Spa and Mobile App Landing readmes include redistribution restrictions and demo-image notices. The new service uses original layouts and no imported template assets. This audit records the files' contents and does not assess licensing for other uses.

## Delivered page and route map

| Path | Purpose |
| --- | --- |
| `/websites.html` | Public landing page for the website-building service: “Give your business a place to land.” |
| `/templates.html` | Five selectable layout previews, plus original reference designs/screens. |
| `/site_intake.html?template=modern` | Owner editor, preview, and explicit publish. |
| `/website-previews/{clean,modern,service,local,personal}.html` | Clearly labeled sample pages. |
| `/api/site/config` | Owner-only loading of saved website fields. |
| `/api/site/preview` | Owner-only preview without saving. |
| `/api/site/generate` | Owner-only publication to tenant configuration. |
| `/t/:slug/site` | Canonical customer-facing page using saved site configuration. |

The service landing page and five sample pages are generated by the same `generateTenantSite` entry used by customers. Rebuild committed static outputs with `npm run build:websites` after renderer, catalog, or CSS changes.

A visitor may browse without signing in. A new owner arriving from the website builder can return there after creating an account; normal Garvey signup retains its existing business-assessment default. Business-assessment completion and access to other tools are not changed.

## Release boundary and remaining checks

This is a review branch; not merged or deployed by this task. No production database writes were used to validate it. Browser sign-in used a local fixture owner; real production signup/sign-in and an actual iPhone remain release checks.

After deployment, the intended public entry is `https://garveyfrontend.onrender.com/websites.html` (also served by the backend). Start there, choose a layout, sign in, enter real business details, preview, publish, and verify the shared link on a phone. Stop at the first failure and report the page, action, and visible error.

Existing legacy template tenants continue to render their prior hub until selecting/publishing a native layout. Already-created `/sites/...` files are not migrated or deleted. The separate legacy `/api/system/activate-full` workflow still uses its historical file-copy materializer; it is not the new website-service entry.

Scope is a content landing page with customer-provided links. Payments, shopping carts, custom domains, multi-page generation, and automatic campaign publishing are not part of this change.
