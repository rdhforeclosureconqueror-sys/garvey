# Garvey Child Genius Combination Framework v1

## Purpose

The Garvey Genius Map uses seven developmental learning dimensions. A report must not reduce a child to one winning category. This framework defines how the platform recognizes a **combination of strengths in context** while preserving separate evidence streams.

## The seven dimensions

| Code | Customer-facing name | Developmental construct | A useful question |
| --- | --- | --- | --- |
| SR | Focus & Self-Control | Self-regulation | “How does the learner organize attention and choose a next step?” |
| CQ | Curiosity & Love of Learning | Inquiry / exploratory drive | “What does the learner want to understand beyond the first answer?” |
| CR | Creativity & Idea Thinking | Idea generation / problem finding | “What possibilities, representations, or approaches does the learner generate?” |
| RS | Thinking & Problem Solving | Reasoning / pattern recognition | “How does the learner analyze structure, compare methods, and justify a choice?” |
| PS | Effort & Resilience | Persistence / challenge tolerance | “How does the learner recover, adapt, and return to a meaningful challenge?” |
| FB | Learning From Feedback | Feedback responsiveness | “How does the learner turn guidance into a changed next attempt?” |
| DE | Interests & Passion Areas | Domain engagement | “What meaningful problems or activities does the learner voluntarily return to?” |

## Report construction rule

For every category named in a customer-facing reading, provide five elements:

1. **What it means** in ordinary language.
2. **Evidence**: a direct child quote, observed behavior, or work sample.
3. **Strength to build on**: an action the learner already uses.
4. **Growth edge**: a next capability, never a deficit label.
5. **Best conditions**: an environment or instructional move that gives the strength productive work to do.

## Combination rule

Do not infer combinations from a single score. Create a combination only when at least two dimensions have evidence in the same response, task, or repeated pattern.

| Combination | Customer-facing description | Evidence pattern to require | Instructional next step |
| --- | --- | --- | --- |
| CQ + RS | Method investigator | Learner asks why/how and tests where a method applies. | Compare methods and test changed cases. |
| RS + FB | Example-to-independence learner | Learner uses an example or correction to change a next attempt. | Fade the example; ask for an independent explanation. |
| SR + PS | Self-leveling learner | Learner manages engagement and returns to challenge with a plan. | Use familiar → varied → stretch progression. |
| CR + RS | Method designer | Learner invents or adapts an approach and reasons about where it fits. | Prototype, test, revise, and state conditions of use. |
| CR + DE | Purpose-driven creator | Learner connects ideas to a meaningful project or audience. | Use authentic design briefs and portfolio artifacts. |
| CQ + CR + RS | Inventive investigator | Learner asks questions, generates possibilities, and tests them. | Run a question → prediction → model → test → revision cycle. |
| CR + RS + DE | Purpose-driven inventor | Learner turns a real need into a solvable design problem. | Define a user, constraint, measurement, and small prototype. |
| SR + PS + FB | Deliberate mastery loop | Learner plans, uses feedback, and persists with changed strategy. | Use short feedback/retry cycles with reflection. |

## Evidence boundaries

- Child self-reflection shows how a learner experiences their own thinking. It is meaningful evidence, but not proof of proficiency.
- Parent or teacher observation shows patterns across settings, but should not overwrite the child's voice.
- Academic work shows performance on a particular task and difficulty level, not a fixed capacity.
- Game or platform data show behavior in that specific activity, not a broad trait by itself.
- A result should always state which stream supports it and what evidence is still needed.

## Required customer-facing language

Use:

- “You described…”
- “This strength seems active when…”
- “A next experiment could be…”
- “This can feel harder when…”
- “Here is what would help you practice it.”

Avoid:

- “You are a [single type].”
- “You have a weakness in…”
- “This proves you are gifted/not gifted.”
- “This result predicts your future.”

## Minimum result layout

1. **Your current learning story** — one paragraph using the learner's own words.
2. **Your active strengths** — top 2–3 dimensions with evidence.
3. **Strengths working together** — 1–3 combinations with a concrete scenario.
4. **Growth edges** — one chosen next capability per strength.
5. **Your best learning conditions** — specific environment and instruction choices.
6. **Your next project or mission** — one authentic application.
7. **What we will notice next** — observable behaviors, not trait labels.

## Validation standard before automated reporting

Before a platform generates a customer-facing reading automatically, it must:

- Preserve the original child response alongside any summary.
- Require enough evidence to name each dimension; otherwise show “still exploring.”
- Separate self-reflection, parent observation, academic work, and platform behavior in the display.
- Allow the child and parent to correct or add context to the reading.
- Never use a single completed assessment to make high-stakes educational decisions.
